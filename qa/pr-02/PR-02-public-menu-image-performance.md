# SIMSIM PR-02 — Public Menu Image & Rendering Performance

**المسار المستهدف:** `https://simsimmenu.com/menu/simsim`  
**النطاق:** تحسين تحميل ورسم الصور في Public Menu فقط، مع الإبقاء على محتوى PR-01 ووظائف المنيو ومصادر البيانات.

## القرار التقني

> التحسين المثبت بالقياس هو **تقديم نسخ WebP متجاوبة من Supabase Storage بحسب مساحة العرض**، مع أبعاد HTML ثابتة، و`loading="lazy"` للصور غير الحرجة، و`fetchPriority="high"` لصورة منتج واحدة فقط تمثل أول بطاقة في ترتيب المحتوى الفعلي. يبقى JPG الأصلي fallback تلقائيًا داخل `<picture>`.

لم يُضف تخزين جديد، ولم يُغيّر schema أو RLS أو URLs المحفوظة في قاعدة البيانات. تحوّل الصورة لا يحدث إلا لروابط Supabase Storage العامة المعتمدة؛ أما أي رابط خارجها فيبقى كما هو.

## خط الأساس وتدقيق الإنتاج

فحص DOM في Production بعد استقرار الصفحة وجد 69 عنصر صورة و61 رابطًا فريدًا، مع ثماني نسخ عرض متكررة للمصادر نفسها. كان 67 عنصرًا بلا `width` و`height` صريحين، و68 عنصرًا يستخدم JPEG خامًا، و22 صورة على الأقل أكبر طبيعيًا من مساحة عرضها بأكثر من 1.5×. كما سجل مراقب الأداء في المتصفح أن عنصر LCP في جلسة الإنتاج كان صورة منتج، لا غلاف المطعم أو صورة الشعار.[1]

| مؤشر التدقيق | قبل PR-02 | ملاحظة |
|---|---:|---|
| عناصر الصور في DOM | 69 | يشمل الغلاف والشعار والتوصيات والأقسام والمنتجات والبانرات. |
| روابط صور فريدة | 61 | توجد نسخ عرض مكررة للمصدر نفسه في سياقات مختلفة. |
| صور بلا أبعاد HTML ثابتة | 67 | فرصة مباشرة لتقليل CLS وحجز مساحة مستقرة. |
| صور JPEG خام | 68 | مصدر رئيسي لهدر البايتات على الجوال. |
| صور Lazy | 64 | بقيت الاستراتيجية، مع ضبط السياق والأبعاد. |
| صور High Priority | 2 | كان الغلاف والشعار كلاهما مرتفعَي الأولوية. |

أُجريت خمس محاولات Lighthouse بمحاكاة هاتف 390×844 وDPR 3 وSlow 4G وCPU 4× مع مسح التخزين. أعاد Lighthouse `NO_FCP` في بيئة Chromium headless، لذلك **لا تُعرض أرقام Lighthouse كقياس صالح قبل/بعد ولا يُدّعى تحسن زمني غير مقاس**. أظهر فحص المتصفح التشغيلي أن Public Menu يعرض مرحلة `AUTH_SESSION` انتقالياً قبل ظهور المحتوى؛ لذلك تبقى متابعة القياس على جهاز فعلي أو RUM بعد النشر ضرورية لعزل أثر bootstrap عن أثر الصور.[2]

## التحسينات المنفذة

| المنطقة | التنفيذ | سبب الاختيار |
|---|---|---|
| الغلاف والشعار | WebP متجاوب عبر `<picture>` و`srcset` و`sizes` وأبعاد صريحة | تخفيض البايتات وحجز المساحة بلا رفع أولوية شبكة غير لازمة. |
| بطاقات المنتجات | تحويلات WebP بأحجام مختلفة بحسب تخطيط `grid` و`list` و`circles` و`showcase` | لا تُحمّل صورة 1080px لبطاقة 108px أو 134px. |
| صورة LCP المرشحة | أول بطاقة فقط في تسلسل: manual best sellers ثم featured ثم favorites ثم أول قسم | طلب `high` واحد فقط؛ لا تتنافس الصور المرئية. |
| الأقسام والتوصيات | WebP مصغر بحدود 36px و134px مع lazy loading | تقليل decode وحمولة العناصر الصغيرة. |
| البانرات ومودال المنتج | WebP متجاوب عند العرض أو الفتح | يحافظ على وظائف العروض والتفاصيل مع fallback JPG. |
| فشل التحويل أو رابط خارجي | يبقى `img src` الأصلي | لا صور وهمية ولا URL جديد غير مدعوم. |

## عينات البايتات الفعلية

تم طلب نفس ملفات Production مباشرة من Supabase Storage، مرة من مسار JPG الخام ومرة من `render/image` بصيغة WebP وحجم العرض المطبق. هذه العينات تثبت أثر التحويل على ملفات حقيقية، لكنها ليست ادعاءً بحجم جلسة كامل.[1]

| الأصل | JPEG الأصلي | WebP المتجاوب | التخفيض |
|---|---:|---:|---:|
| أول صورة منتج، 480px، جودة 72 | 84,984 B | 23,878 B | **71%** |
| غلاف المطعم، 480px، جودة 76 | 162,342 B | 51,466 B | **68%** |
| شعار المطعم، 64px، جودة 78 | 47,351 B | 3,064 B | **93%** |

## التحقق

تم تشغيل الاختبارات الكاملة والبناء بعد تطبيق التغييرات. نجح **297 اختبارًا عبر 23 ملف اختبار**، بما في ذلك اختبارات توليد رابط التحويل و`srcset`. كما نجح Production build و`git diff --check`.[3]

في Preview المحلي ببيانات مطعم سمسم الحقيقية، ظهرت الأقسام والمنتجات والصور من دون صورة مكسورة. اختار المتصفح WebP المحوّل لـ22 صورة في DOM، ولم يختر fallback الخام في المتصفح الداعم، وكانت هناك صورة واحدة فقط ذات `fetchPriority="high"`. أضافت الصور 68 زوجًا من خصائص العرض والارتفاع، وظلت أبعاد بطاقات شبكة المنتجات مستقرة بصريًا. تم التحقق أيضًا بلقطة هاتف 390×844 بعد اكتمال التحميل.[1]

| عنصر القبول | الحالة |
|---|---|
| لا تغيير Schema أو RLS أو API أو محتوى المنيو | **PASS** |
| لا صور وهمية أو تغيير لمصادر البيانات | **PASS** |
| WebP و`srcset` لروابط Supabase العامة مع JPG fallback | **PASS** |
| Lazy loading وصورة عالية الأولوية واحدة | **PASS** |
| أبعاد ثابتة للصور المعدّلة | **PASS** |
| صور مكسورة في Preview | **0** |
| الوظائف الأساسية للمنيو | **PASS** في Preview |
| Lighthouse before/after موثوق تحت headless | **NOT VERIFIED** بسبب `NO_FCP` البيئي؛ لا ادعاء رقمي زائف |

## ملاحظات ما بعد النشر

ينبغي بعد دمج PR-02 تشغيل قياس من هاتف فعلي أو RUM على Production للمقارنة الزمنية، مع فصل زمن `AUTH_SESSION` عن زمن تحميل الصورة. لا تُنفذ أي خطوة إضافية الآن ضمن هذا PR؛ لا preprocessing في الرفع، ولا CDN جديد، ولا تعديل في PR-01.
