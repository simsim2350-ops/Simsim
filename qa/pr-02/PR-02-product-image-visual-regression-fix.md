# SIMSIM PR-02 — Product Image Visual Regression Fix

**المسار:** `/menu/simsim`
**النطاق:** إصلاح تضخم الصورة الظاهري بعد PR-02، مع الإبقاء على WebP و`<picture>` و`srcset` و`lazy loading` واستراتيجية LCP كما هي.

## السبب الجذري

> لم تكن المشكلة في CSS للبطاقة أو في حجم الحاوية المرسومة. ظلَّت بطاقة `grid` وحاوية الصورة والصورة المعروضة نفسها بالأبعاد ذاتها قبل PR-02 وبعده. سبب الانحدار كان أن تحويل Supabase في PR-02 طلب **العرض فقط**. احتفظ المورد الناتج بنسبة/ارتفاع غير مناسبين للحاوية، ثم قام `object-fit: cover` بقصه داخل مربع البطاقة؛ فبدت المنتجات أكبر أو أكثر تكبيرًا رغم عدم تغير Layout.

في أول صورة منتج، كان مورد PR-02 بعرض 480 ينتج فعليًا بحجم طبيعي 467×840 داخل حاوية مربعة 464×464. وفي بطاقة التوصية الأفقية، كان المورد 134×241 داخل حاوية 131×96. هذا عدم توافق بين **نسبة المورد** ونسبة الحاوية، وليس تضخمًا في `ProductCard`.

## الإصلاح المحدود

تم تعديل مولد رابط WebP فقط. عندما يمرر السياق أبعاد حاوية ثابتة، يولّد `srcset` الآن لكل candidate:

```text
width=<candidate>&height=<candidate × نسبة الحاوية>&resize=cover&quality=<current>&format=webp
```

لم يتغير CSS للبطاقة أو Grid أو المسافات أو الخطوط أو النصوص أو الأزرار أو منطق المنيو. بقيت الحاويات الأصلية كما هي: `grid` مربع، و`showcase` بنسبة 4:3، و`list` و`circles` مربعان، و`recommendations` بنسبة 134×96. بقيت URLs خارج Supabase Storage على المصدر الأصلي كـfallback، وJPG موجودًا دومًا كبديل داخل `<picture>` للمتصفحات غير الداعمة لـWebP.[1]

| الحالة | بطاقة grid | حاوية/صورة مرسومة | المورد الطبيعي لأول منتج | ملاحظة |
|---|---:|---:|---:|---|
| قبل PR-02 | 467×531 | 464×464 | 1080×864 JPG | التصميم المرجعي. |
| PR-02 قبل الإصلاح | 467×531 | 464×464 | 467×840 WebP | نفس CSS، لكن مورد طويل قُص داخل مربع. |
| بعد الإصلاح | 467×531 | 464×464 | 467×467 WebP | مورد مربّع يطابق حاوية grid. |

| السياق | النسبة المحفوظة في المصدر بعد الإصلاح |
|---|---|
| `grid` و`circles` و`list` | مربع (`1:1`) |
| `showcase` | `4:3` |
| `recommendations` | `134:96` |
| الغلاف والشعار والبانرات والمودال | تستخدم أبعاد سياق العرض المعلنة نفسها؛ لا تغيير في الحاوية المرئية. |

## الأثر على الأداء

بقي WebP و`srcset` فعالين. لنفس صورة المنتج الحقيقية، كان JPG الخام **84,984 B**، وتحويل PR-02 السابق بعرض فقط **23,878 B**، والتحويل المربّع المصحح **16,820 B**. لذلك حافظ الإصلاح على خفض **80%** مقابل JPG الخام، بل خفّض مورد الصورة **29.5%** مقارنة بتحويل العرض فقط، من دون تقليل جودة التحويل المحددة أو تحميل JPG في متصفح داعم لـWebP.[1]

## التحقق البصري والمتجاوب

تم التقاط وتحليل Public Menu بعد إغلاق البانر على المقاسات 360×800 و390×844 و414×896 و768×1024 و1024×900 و1440×900. لم تسجل الجلسات أي صورة مكسورة، وأظهرت الجلسة أن أول بطاقة فقط بقيت `eager/high` بينما بقيت الصور الأخرى `lazy/auto`. في لقطة 390×844 عادت بطاقات المنتج إلى الشبكة المربعة المتوازنة، وبقيت التوصيات ضمن حجمها الأفقي الأصلي. لم يظهر قص خارج الحاوية أو انتقال للمحتوى.[1]
