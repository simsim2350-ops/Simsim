# SIMSIM — تطوير خطوة أقسام المنيو في Onboarding

**إعداد:** Manus AI  
**النطاق:** خطوة «أقسام منيوك» فقط، مع الحفاظ على مخطط البيانات وواجهات Supabase ومسار إنشاء المنيو الحالي.

## ملخص التنفيذ

تم تحويل خطوة الأقسام من قائمة قوالب محلية مؤقتة إلى واجهة إدارة للأقسام الحقيقية في `public.categories`. تحمّل الخطوة الأقسام المرتبطة بالفرع الرئيسي للمطعم وتعرضها مرتبة بحسب `sort_order`. إضافة القسم والحذف وإعادة الترتيب تكتب مباشرة في Supabase، وتبقى القوالب الجاهزة مجرد اختصارات لإدراج أقسام حقيقية وليست مصدر عرض مستقل.

| المجال | التنفيذ |
|---|---|
| مصدر البيانات | `public.categories`، مقيّد بـ`branch_id` للفرع الرئيسي الذي تعيده `ensurePrimaryBranch` |
| إنشاء القسم | `INSERT` حقيقي يحفظ `restaurant_id` و`branch_id` و`name` و`emoji` و`is_visible` و`sort_order` |
| منع التكرار | تحقق محلي ثم تحقق قراءة من قاعدة البيانات بالفرع والاسم قبل الإدراج |
| الحذف | `DELETE` بالقسم الحقيقي بعد تأكيد صريح عبر `ConfirmDialog` |
| الترتيب | تحديث تفاؤلي مع حفظ `sort_order` لكل قسم؛ يعيد القائمة السابقة عند فشل الحفظ |
| الاستئناف | عند `onboarding_step = 'categories'` يجلب الصفوف الحقيقية مرة أخرى، ولا يعيد إنشاء قالب محلي |
| الأصناف | تستخدم معرف القسم الحقيقي `category.id`، ولا يعاد إدراج الأقسام عند إنشاء المنيو |

## التغييرات الوظيفية

يستخدم `loadOnboardingCategories` الفرع الرئيسي للمطعم ثم يقرأ الأقسام باستخدام `branch_id` وترتيب `sort_order`. لذلك فإن Refresh أو العودة إلى خطوة الأقسام يعرضان ما تم حفظه سابقًا بدل أي بيانات محلية مؤقتة.

تعرض القوالب المتوافقة مع نوع النشاط كأزرار إضافة. عند النقر، تستدعي `persistCategory` وتدرج صفًا حقيقيًا في جدول `categories`. إذا كان القسم موجودًا بالفعل يظهر باعتباره مضافًا، ولا يمكن إدخاله مرتين. الإضافة اليدوية تفتح Bottom Sheet على الجوال ونافذة مركزية على الشاشات الأكبر، مع اسم قسم مطلوب وأيقونة اختيارية متوافقة مع الحقل القائم `emoji`.

قبل انتقال المستخدم إلى خطوة الأصناف، يجب أن تحتوي القائمة المحفوظة/المحمّلة على قسم واحد على الأقل. كما أن `finish` لم يعد ينشئ صفوف أقسام جديدة؛ بل يقرأ الأقسام المخزنة ويتحقق منها، ثم ينشئ الأصناف المقترحة المختارة فقط باستخدام `category_id` الحقيقي.

## واجهة وتجربة الاستخدام

حافظت الواجهة على RTL وهوية SimSim. تتضمن رأسًا واضحًا ووصفًا قصيرًا، وصندوق قوالب دافئًا وخفيفًا، وقائمة أقسام تعرض العدد الحي، وحالة فارغة، وSkeleton أثناء التحميل، ورسالة خطأ مع إعادة محاولة. لكل قسم إجراءات واضحة للحذف والتحريك للأعلى والأسفل، مع السحب على Desktop كخيار إضافي. أزرار الرجوع والمتابعة تبقى Sticky بصريًا قرب أسفل البطاقة خلال التمرير، ويظل زر المتابعة معطلًا عند عدم وجود قسم أو أثناء عملية حفظ/تحميل.
