# SIMSIM — تطوير خطوة اختيار نوع النشاط في Onboarding

## النطاق

طُوِّرت خطوة اختيار نوع النشاط في `src/pages/Onboarding.jsx` لتستخدم سجل المطعم الحقيقي في Supabase، من دون إنشاء جدول أو عمود جديد ومن دون تغيير بنية الرحلة أو مصادر بيانات المنيو.

> الحقل القائم هو `public.restaurants.type`، ونوعه `text`، وقيمته الافتراضية الحالية `'restaurant'::text`. [1]

## 1. تدفق البيانات الحقيقي

| المرحلة | السلوك المنفذ |
|---|---|
| تحميل Onboarding | يقرأ سجل المطعم الحالي، ويستعيد نوع النشاط المحفوظ إذا كانت خطوة الاستئناف `type_selected`. |
| اختيار بطاقة | يحدد البطاقة فورًا بصريًا ثم يحفظ الاختيار في `restaurants.type` و`onboarding_step: 'type_selected'`. |
| نجاح الحفظ | يستدعي `fetchRestaurant(user.id)` ويتحقق أن السجل المعاد يحمل النوع المختار نفسه. |
| زر التالي | يبقى معطلًا قبل الاختيار، ولا ينتقل إلى الأقسام قبل نجاح الحفظ أو التحقق من أن الاختيار المحفوظ يطابق الاختيار الحالي. |
| فشل الحفظ أو refresh | يبقى المستخدم في خطوة النوع، وتظهر رسالة عربية آمنة، ولا ينشأ انتقال إلى الأقسام. |
| العودة من الأقسام | يعيد `returnToBusinessType` النوع المحفوظ إلى البطاقة المحددة من دون فقده. |
| Refresh أو مغادرة الصفحة | إذا حُفظ الاختيار قبل الضغط على التالي، تستأنف الصفحة عند `type_selected` وتظهر البطاقة المختارة. |

## 2. التقدم الموحد

كان مؤشر Onboarding يعرض رقم خطوة فعليًا وفي الوقت نفسه عداد جاهزية مختلفًا باسم «الأساسيات»، ما خلق رقمين متعارضين. أصبح المصدر الوحيد للتقدم هو مصفوفة `STEPS` القائمة:

```js
الخطوة {stepIndex + 1} من {STEPS.length}
```

وشريط التقدم يستخدم المعادلة نفسها. نقلت جاهزية المشاركة إلى `MenuReadinessCard` في مراحلها الخاصة، ولم يعد مؤشر خطوات Onboarding يعرض عدادًا ثانيًا غير متعلق بالخطوة الحالية.

## 3. الواجهة والإتاحة

تستخدم الخيارات الآن SVG محلية متسقة بدل Emoji في بطاقات نوع النشاط. لكل بطاقة حالة `aria-pressed`، وحد برتقالي، وخلفية برتقالية خفيفة، وcheck icon واضحة عند الاختيار. النموذج يدعم لوحة المفاتيح، وحالة `aria-busy`، ورسالة خطأ `role="alert"`، وحلقة focus برتقالية مرئية.

| العنصر | النتيجة |
|---|---|
| مطعم | بطاقة SVG مع حالة اختيار حقيقية مرتبطة بالقيمة `restaurant`. |
| كافيه / كوفي | بطاقة SVG مع القيمة `cafe`. |
| فود ترك | بطاقة SVG مع القيمة `truck`. |
| مطبخ سحابي | بطاقة SVG مع القيمة `cloud`. |
| التالي | معطل قبل الاختيار، ويعرض «جاري الحفظ...» أثناء التنفيذ. |
| الرجوع | يعيد المستخدم لمعلومات المطعم أو يعيد اختيار النوع من الأقسام مع إبقاء الاختيار. |

## 4. حماية الموثوقية

| الخطر | الحماية |
|---|---|
| ضغط متكرر | `typeSaveInFlight` مع حالة `saving` وتعطيل عناصر النموذج. |
| خطأ Supabase راجع في `error` | `if (error) throw error` ثم رسالة آمنة ومنع الانتقال. |
| refresh لا يعيد السجل الصحيح | يتحقق الكود من وجود المطعم ومن مطابقة `refreshedRestaurant.type` للقيمة المختارة. |
| اختيار افتراضي غير مقصود | لا يعامل default `restaurant` كاختيار سابق إلا عندما تكون `onboarding_step === 'type_selected'`. |
| بيانات وهمية | لا توجد بيانات نوع نشاط في LocalStorage أو mock؛ تستخدم الواجهة عمود `restaurants.type` فقط. |
