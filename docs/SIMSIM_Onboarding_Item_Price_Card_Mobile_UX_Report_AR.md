# SIMSIM — إصلاح بطاقة السعر الحقيقي في اختيار الأصناف

**إعداد:** Manus AI  
**النطاق:** واجهة بطاقة الصنف في مرحلة «اختر أصنافك» ضمن Onboarding فقط.

## المشكلة

كان صف السعر داخل بطاقة الصنف المحدد يستخدم تخطيطًا أفقيًا يجمع عنوان «السعر الحقيقي» وحقل الإدخال والعملة في مساحة ضيقة. وعلى مقاسات الهاتف كانت هذه العناصر تتزاحم مع محتوى الصنف، ما يضعف وضوح الاسم والسعر.

## التنفيذ

أصبح لكل صنف صف معلومات مستقل يضم زر الاختيار والأيقونة والاسم ووصف المصدر وحالة «محدد». اسم الصنف لم يعد يقتصر على سطر واحد؛ يستخدم `overflowWrap: 'anywhere'` كي يبقى مرئيًا حتى مع الاسم الطويل.

عند التحديد فقط، يظهر بعد مسافة رأسية وخط فاصل صف سعر مستقل كامل العرض. يحتوي الصف على label ثابت ومحاذٍ لـRTL بعنوان «السعر الحقيقي»، وتحته input بعرض `100%` وارتفاع لمس `46px` أو أكثر. توضع العملة داخل الحقل في منطقة منفصلة بحد داخلي، مع مساحة padding محجوزة لها؛ لذا لا يتداخل الرقم أو placeholder مع العملة.

عند عدم التحديد لا يظهر الحقل، وتبقى عبارة «السعر يضاف بعد التحديد». لم يتغير منطق التحقق أو مصدر القيمة أو حفظها؛ السعر ما زال يؤخذ حصريًا من `itemPrices` بعد الإدخال الصريح من المالك.

## الضمانات

| المتطلب | التنفيذ |
|---|---|
| فصل معلومات الصنف والسعر | صف معلومات مستقل ثم بطاقة سعر كاملة بعد divider. |
| منع قص الاسم | `minWidth: 0` و`overflowWrap: 'anywhere'` بدل ellipsis. |
| منع تداخل السعر | input بعرض كامل و`boxSizing: border-box` مع padding محجوز للعملة. |
| RTL | حاوية السعر `dir="rtl"` وlabel بمحاذاة يمين؛ الرقم نفسه `ltr` للقراءة. |
| unselected state | لا يظهر input؛ تظهر رسالة السعر بعد التحديد فقط. |
| selected state | يظهر badge «محدد» مع border برتقالي وhighlight متسق مع الهوية. |
| CTA | لم يتغير موضعه أو منطقه؛ لا يزال يعتمد عدد الأصناف المحددة الفعلي. |
| منطق الأسعار والحفظ | لم يتغير: لا سعر من القالب ولا تغيير في قاعدة البيانات أو API. |
