# Simsim Marketing CMS — Phase 2 Design

> **النطاق:** تنفيذ على Staging فقط. يوسّع `marketing-ssr/` وواجهة Super Admin الحالية، ولا يغيّر تطبيق الطلبات أو المنيو العام أو تدفقات المصادقة أو إعدادات النطاق وVercel الإنتاجية.

## الهدف التشغيلي

تظل المعمارية كما هي: يحرر Super Admin المحتوى في Vite، وتنفذ Supabase RPC عمليات التغيير المفوضة، ثم تقرأ Next.js نسخًا منشورة فقط من الخادم. لا تُفتح جداول CMS إلى المفتاح العام؛ تستمر القراءة العامة عبر RPC محدودة.

| الطبقة | الامتداد المقترح | الضمان |
|---|---|---|
| Super Admin | إدارة صفحات ولغات ومراجعات وأقسام typed وإعدادات ووسائط | لا يحتاج المحرر إلى تعديل الشفرة للعمليات التسويقية اليومية. |
| Supabase RPC | CRUD للصفحات، إعدادات، مراجعات، وسائط وإلغاء نشر | كل Mutation تتحقق من `is_platform_admin()` داخل الخادم. |
| Marketing CMS | حالة الصفحة `active/archived` ومؤشرات نشر مستقلة للغة | لا تتغير الجداول التجارية `plans` و`plan_features` و`feature_flags`. |
| SSR | قارئ صفحات ولغات عام، metadata بفallback عام، وسجل أقسام موسع | لا تظهر أي مسودة أو بيانات إدارية للعامة. |
| التخزين المؤقت | `marketing-page:<slug>:<locale>` و`marketing-settings:<locale>` | إبطال موجّه للصفحة/اللغة فقط، دون إعادة بناء كاملة. |

## نموذج الصفحات والإصدارات

يُضاف soft archive إلى `marketing_pages`، وتصبح الصفحة قابلة للإنشاء والنسخ والأرشفة والحذف الآمن. الحذف الفعلي يُقبل للصفحات غير المنشورة فقط؛ الصفحة التي سبق نشرها تُؤرشف كي لا تضيع المراجعات أو الروابط بالخطأ. تظل `marketing_page_revisions` المصدر الوحيد للإصدارات، وتُضاف دوال تعرض تسلسل الإصدارات وتعيد نسخة مختارة إلى مسودة جديدة قبل نشرها.

> لا يُنسخ السعر أو مقدار القدرات إلى CMS. يستقبل قسم `PRICING` فقط طبقة العرض: ترتيب الباقة، ظهورها، الشارة، الوصف وCTA؛ بينما يظل السعر والمزايا المضمنة من RPC `marketing_public_plans`.

## سجل الأقسام

تضاف الأنواع `VIDEO` و`IMAGE_TEXT` و`TESTIMONIALS` و`STATS` و`LOGOS` و`COMPARISON` و`CONTACT` إلى سجل موحّد. لكل نوع مخطط Zod، بيانات بداية، محرر حقول متخصصة، Renderer خادمي، ومعالجة unknown type التي تتخطاه وتترك أثرًا تشخيصيًا بدل كسر الصفحة. تستخدم الوسائط روابط public من مكتبة الوسائط، وتتحقق المخططات من طول النصوص والرابط الآمن وحجم القوائم.

## الإعدادات وSEO

تستعمل `marketing_site_settings_revisions` القائمة بدل إنشاء جدول جديد. يحرر Super Admin الاسم والشعار والتنقل والتذييل ووسائل التواصل وبيانات الاتصال والـCTA الافتراضي وSEO العام. تتقدم قيم SEO للصفحة على القيم العامة، وتبقى قيم seed المحلية fallback أخيرًا فقط عندما لا تتوفر بيئة Supabase أو لا توجد إعدادات منشورة.

## الأمان والتدقيق

تظل كل دوال الإدارة `SECURITY DEFINER` بعبارة `set search_path = public`، مع سحب التنفيذ عن `anon` و`public` ومنحه لـ`authenticated` فقط. تؤكد كل دالة `is_platform_admin()`؛ لذلك لا تتحول إتاحة RPC للمستخدمين المصادقين إلى قدرة إدارية. ستبقى دوال القراءة العامة والمعاينة متاحة عمدًا: الأولى لا تُرجع إلا مؤشرات نشر؛ والثانية تتطلب Token عشوائيًا مجزأً وقصير العمر.

يُستخدم `platform_audit_logs` القائم. تُضاف أحداث دقيقة مثل `marketing.page_created` و`marketing.page_archived` و`marketing.draft_saved` و`marketing.revision_published` و`marketing.preview_generated` و`marketing.settings_published` و`marketing.media_updated`، دون حفظ token المعاينة نفسه.

## النشر والتخزين المؤقت

بعد نشر/إلغاء نشر/استرجاع صفحة أو إعدادات، يستدعي Vite الـWebhook الموجود بمفتاح خادمي مُخزن في البيئة. يستبدل الـWebhook إبطال المسار العام واسع النطاق بإبطال tag (`revalidateTag(tag, { expire: 0 })`) ومسار الصفحة المتأثر عند الحاجة. توصي وثائق Next.js باستخدام Tags لإبطال بيانات دقيقة، وإتاحة `revalidateTag` داخل Route Handler.[1]

## الاختبارات

تغطي اختبارات الوحدة مخططات الأقسام والـSEO والإعدادات. وتغطي اختبارات التكامل RPC التفويض، الإصدارات، إلغاء النشر، وحماية القراءة العامة. يضيف اختبار E2E رحلة Super Admin الحقيقية عند توافر جلسة اختبار إدارية آمنة؛ وإذا لم تتوفر لن تُسجل النتيجة كنجاح، بل تبقى فجوة صريحة في التقرير.
